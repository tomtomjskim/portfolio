# 실무형 AI 자동화 — 로컬 LLM과 검증 책임 분리

## 핵심 질문

AI를 사용할 수 있는 업무라고 해서 전부 AI에 맡겨야 하는가? 자연어 처리, 규칙 기반 코드, 사람 검수의 책임을 어디서 나눌 것인가?

## 한눈에 보기

| 구분 | 요약 |
|---|---|
| **문제** | 번역·복사·언어팩 반영이 반복되고 소형 모델에 한계가 있음 |
| **판단** | 자연어는 로컬 LLM, 파일 변환은 규칙 기반 코드, 최종 판단은 사람 |
| **근거** | 실제 반복 사용한 언어팩 작업 흐름과 공개 검증 원칙 |

## 문제

다국어 UI 언어팩 작업에서 다음 조작을 언어별로 반복해야 했습니다.

```text
한국어 문장 확인
→ 언어별 번역기 실행
→ 결과 복사
→ 코드 입력
→ PHP 언어팩 반영
→ JSON 변환
```

문제는 번역 품질뿐 아니라 사람이 같은 조작을 계속 반복해야 한다는 점이었습니다.

## 업무 환경과 제약

- 전용 GPU가 없는 내부 개발 PC
- CPU 기반 추론
- Gemma 3 계열 소형 모델
- 문장별 처리 속도와 번역 품질의 한계
- 언어팩 구조는 정확히 보존해야 함
- 결과를 사람이 확인해야 함
- 번역 서버 소스와 내부 경로는 비공개

## 확인 과정

업무를 하나의 “AI 번역 문제”로 보지 않고 출력의 성격에 따라 나눴습니다.

| 업무 | 출력 특성 | 기본 선택 |
|---|---|---|
| 자연어 번역 | 여러 합리적 표현과 문맥 판단이 필요 | LLM 초안 |
| key/value 구조 보존 | 규칙이 명확하고 같은 입력에 같은 구조 필요 | 규칙 기반 코드 |
| PHP 파일 생성 | 포맷과 이스케이프 규칙이 명확 | 규칙 기반 코드 |
| JSON 변환 | 정확한 구조 변환 | 규칙 기반 코드 |
| 오역·문맥·최종 반영 | 업무 책임과 판단 필요 | 사람 검수 |

## 판단

자연어 번역과 파일 생성을 같은 모델에 맡기지 않았습니다.

```mermaid
flowchart LR
    K[한국어 key/value] --> PY[내부 Python 서버]
    PY --> L[Ollama / Gemma 3]
    L --> T[영어·일본어·중국어 초안]
    T --> P[별도 언어팩 프로그램]
    P --> H[PHP 언어팩]
    H --> J[JSON 변환]
    J --> R[사람 검수]
```

- **LLM:** 영어·일본어·중국어 번역 초안
- **규칙 기반 프로그램:** key/value 구조를 받아 PHP 언어팩을 만들고 JSON으로 변환
- **사람:** 번역 맥락과 오역 확인, 최종 반영 판단

## 선택 기준과 대안

소형 로컬 모델은 문장 하나에 수십 초가 걸릴 수 있었고 일부 결과는 다시 확인해야 했습니다. 순수 처리 속도만 보면 빠르지 않았습니다.

다만 사람이 언어별 번역기·복사·코드 입력을 순차 반복하는 대신, 초안 생성을 다른 작업과 병렬로 진행하고 파일 변환은 프로그램에 맡길 수 있었습니다.

도입 전 기준 측정값을 남기지 않았으므로 생산성 향상률, 정확도, 비용 절감률은 주장하지 않습니다.

## 구현

### 1. 로컬 번역 초안 생성

- Python 서버가 Ollama를 호출
- 한국어 key/value를 입력
- 영어·일본어·중국어 초안 생성
- 전용 GPU 없이 내부 PC에서 실행

### 2. 규칙 기반 언어팩 생성

Ollama 호출과 파일 생성은 별도 책임으로 분리했습니다.

```text
번역 초안
→ PHP 언어팩 생성
→ JSON 변환
```

모델이 파일 구조를 임의로 생성하도록 두지 않고, 규칙이 명확한 단계는 일반 프로그램이 담당합니다.

### 3. 사람 검수와 수동 보정

소형 모델의 오역이나 문맥이 어색한 결과는 사람이 수정하고 최종 반영합니다. 완전 자동 번역 품질을 전제로 하지 않습니다.

## 검증과 실제 사용

- 프론트 개발자가 실제 언어팩 작업에서 반복 사용
- 번역 결과를 사람이 확인한 뒤 반영
- PHP 언어팩 생성과 JSON 변환을 모델의 자연어 출력과 분리
- Agent 개발 작업에서도 모델의 완료 보고와 실제 실행 결과를 분리
- 회사 실무의 모든 단계가 CI에서 자동 강제됐다고 주장하지 않음

현재 공개 근거만으로는 placeholder·HTML 태그·줄바꿈 보존을 별도 검사기로 자동화했다고 말할 수 없습니다. 이 항목은 향후 원천 확인이 필요한 세부 범위입니다.

## 한계

이 사례가 증명하지 않는 범위:

- 회사 전체 AX 플랫폼 책임

- GPU 추론 플랫폼 운영
